Model lifecycle
Validation compares simple baselines with boosted trees. Calibration sets interval widths. Bundles carry file hashes and dependency versions. Promotion and rollback are explicit local operations; the API never accepts uploaded model files.
Bounded access
Protected routes require authentication. Request size, history length, and call rate are limited. Docker runs a single non-root process with a read-only model mount. A public deployment still needs managed secrets, TLS, and service-level monitoring.

    


    

      
02 / WHAT HAPPENED AFTERWARD
Measure the misses.
A historical replay connects each forecast to an observation only after its target hour is complete. Repeated outcomes are idempotent; conflicting outcomes are rejected.

      
HISTORICAL REPLAY, NOT LIVE TRAFFIC
Coverage is measured against a nominal 80% interval. Input-shift statistics are descriptive, not an automatic retraining decision. Missing outcomes are separate from measured errors.

    Evidence has limits
    The assistant can compare saved models, find their largest errors, and explain the documented methodology. It declines live predictions, missing experiment scope, secrets, and unsupported claims.
    Offline tests are not an LLM benchmark
    Fixed questions exercise numerical answers, citations, refusal, and mocked tool-planner responses. Real provider performance, latency, and cost remain unmeasured until a separately authorized API evaluation.
    
    
    

    
    04 / AN INDEPENDENT DATASET
    Keep the
    uncomfortable result.
    The protocol was locked before downloading a separate whole-household dataset. All six models used shared origins. This is a replication, not a future appliance-data test.
    The validation-selected model lost to the last-value baseline at one hour. The six-hour model improved. One household and sparse origins do not establish general performance. Missing-hour targets were excluded consistently rather than filled with invented actuals.
